# Peak

## 核心结论

- 《Peak》的核心价值在于通过低门槛高频互助设计，实现了非强制的自然社交合作体验
- 其体力条系统是设计的核心基础，将所有状态统一整合，兼顾直观性与深层规则复杂度
- 游戏的难度、随机地图等争议点本质是开发模式与设计取舍的结果，并非单纯的缺陷

## 基本介绍

催化剂式合作游戏

多人登山联机支持1-4人

玩家扮演童子军流落荒岛爬山

目标为登顶点燃求救信号

类比自驾游鼓励自然社交

## 现有联机合作游戏

- 多围绕  能力/信息边界  做设计

- 强制划分固定职责如法师、战士

- 玩家需按  预设流程  完成任务

- 传统合作游戏社交体验不自然 类似被迫参加旅游团的体验

## 开发与定位

牛仔式开发 短周期快速原型验证 无严格版本管理，半年发售

处于合作游戏光谱中间位置

优先拟真代入，放弃强制同步

## 关键交互设计

- 道具与生态：体验触发器
- 拉一把： 队友无成本将半挂玩家拉上平台。高频无偿互助，构建互帮互助的行为模式
- 绳子道具：固定长度可截断，需沟通确认下放长度。强制玩家实时沟通，避免资源浪费
- 背包交互：需落地取放，队友可直接互取物品。模拟现实熟人分享，自然产生互动
- 场景说明书：规则以场景纸张呈现，无UI引导。鼓励玩家朗读分享，传递信息
- 曼德拉草：混乱场景，还可以用来更新一些受伤状态。
- 被起受伤玩家：需要与被需要。信任的建立
